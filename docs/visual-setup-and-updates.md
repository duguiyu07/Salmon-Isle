# 可视化连接与程序更新（1.1.0）

## 先连接网站，再连接桌面

网站程序先更新到 1.1.0，原有数据目录继续使用，无需先运行内容迁移命令。

1. 登录在线后台，打开「提交 → 仓库连接」，填写已创建的 GitHub 私有仓库 HTTPS 地址。
2. 点击「前往 GitHub 授权」。向导会自动填写本站专用 GitHub App 的配置；在 GitHub 确认创建，选择仅安装到目标内容仓库，再完成用户授权。
3. 返回网站，点击「预检网站内容」。预检只生成候选工作区，不修改原内容，也不切换线上版本。
4. 核对文章、页面、文件夹、媒体、编辑稿、回收站和变更文件清单。默认以当前网站内容为准；已有内容仓库中的移除项也会出现在清单中。其他业务项目的仓库会被拒绝。
5. 点击「备份并确认接入」。服务器先完整备份，再生成迁移提交、推送和校验上线快照。完成后显示「网站已同步」。
6. 安装桌面客户端，在「提交 → 仓库连接」填写同一仓库地址和网站地址。目录及分支默认自动选择，首次访问 GitHub 时由内置凭据管理器引导到系统浏览器登录。

服务器 GitHub App 的密钥保存在网站的持久化运行目录中，桌面凭据保存在 Windows 凭据存储中。两者都不会进入内容仓库。重新授权会复用已有应用；原应用已删除时，在高级设置勾选「重新创建授权应用」。

首次迁移时原网站文件保持原样。若预检后网站有新的编辑，或远程出现新提交，迁移会停止并要求重新预检。推送失败会保留已经创建的提交及备份，点击重试继续推送。

## 日常使用

保存与自动保存只修改工作区。准备发布、准备更新、准备撤回后，在「提交 → 工作区」核对文件和 diff，填写或自动生成提交信息，再整批提交并推送。「历史记录」可查看提交及其父版本差异。

网站收到签名有效的 GitHub push 通知后立即检查，同时保留每 30 秒轮询。推送成功和网站上线是两个状态；格式、权限或媒体引用校验失败时，访客继续看到上一版本。

媒体库每页 24 项，支持文件名、类型和引用状态组合筛选。「无引用」统计当前工作区、编辑稿（含合并基线）及回收站，不包括 Git 历史和旧上线快照。引用卡片在新标签页打开相应版本的管理员预览。

存在有效引用的资源不能删除。仅被回收站引用时，可以强制删除：相关引用改成内置占位资源，恢复文章后仍显示占位。这些变更随同一次提交同步，旧上线快照在切换前不受影响。

## 更新桌面客户端

从 1.0.0 升级时，直接运行新版安装程序，选择现有安装位置即可覆盖，不需要卸载。连接配置、本地内容、凭据和恢复稿位于安装目录以外。

从 1.1.0 起，点击右上角「更新」：

1. 检查更新。
2. 下载更新，程序会校验下载内容。
3. 点击「保存并重启安装」。所有编辑窗口保存成功后才开始覆盖升级；版本冲突或保存失败会阻止安装，解决后可以重试。

正式发布的客户端会内置源码项目的更新地址；也可以从已连接网站的公开程序信息获取，或在「更新源」中填写一次 HTTPS 目录。该目录需要提供同一次构建的 latest.yml、安装程序和 blockmap。安装包发布前，客户端不会凭空出现可下载的新版本。

ZIP 版适合便携运行；需要应用内覆盖升级时使用 NSIS 安装版。Windows 代码签名在发布流程中配置，更新器保留安装包中声明的发布者验证。

## 更新网站

后台右上角「更新」显示当前网站版本、新版本和发布说明。正式镜像内置源码项目的 release.json 地址；自行部署时，也可在此配置一次发布源。

有新版本时，后台生成带具体镜像版本的命令：

```sh
sh scripts/update-site.sh --image ghcr.io/owner/source:1.2.0
```

Windows Docker 主机：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/update-site.ps1 -Image ghcr.io/owner/source:1.2.0
```

脚本在现有部署目录执行：先准备新镜像，停止写入后备份 data，再保留数据卷启动新版本并等待健康检查。启动失败会恢复之前的镜像，原内容不被清空。备份位于 backups/program-时间；其中包含认证和授权数据，应按私有文件保存。

指定镜像后，脚本只更新 .env 中的 SALMON_WEB_IMAGE，其他部署设置保留。使用源码 Git checkout 部署时，不带参数会执行快进拉取和构建；有源码改动或不属于 Git checkout 时停止，不会覆盖本地文件。

首次部署服务器、域名和 HTTPS 仍按原部署说明完成。网站进程不需要访问 Docker socket。

## 程序发布源与内容仓库分开

| 仓库或发布位置 | 存放内容 |
| --- | --- |
| 私有内容 Git 仓库 | 文章、页面、文件夹、编辑稿、媒体、回收站 |
| 软件源码项目 Releases | 安装程序、ZIP、源码包、latest.yml、release.json |
| 软件源码项目 GHCR | 网站程序镜像 |
| 网站持久化数据目录 | 网站设置、认证、GitHub App 授权、运行状态、上线快照 |

项目自带 GitHub Actions 发布流程。把源码放入自己的源码仓库，保持根目录与 desktop/package.json 的版本一致，再推送相应的 v版本 标签。流程生成网站镜像、Windows 客户端和更新元数据；发布源会自动使用该源码仓库地址，源码不内置任何实际私有内容仓库。

公开分发时，将 GHCR 镜像设为公开可拉取。需要 Windows 签名时配置 WINDOWS_CSC_LINK、WINDOWS_CSC_KEY_PASSWORD 和 WINDOWS_PUBLISHER_NAME。需要本机构建时：

```powershell
npm run desktop:package
npm run release:source
npm run release:metadata -- --repository owner/source
```

将 dist/desktop 中本版本的安装程序、ZIP、blockmap、latest.yml、release.json 和校验文件发布到同一 Release。后续只需发布新版本，用户无需反复配置更新源。
